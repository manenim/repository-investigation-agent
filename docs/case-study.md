# Trace: an independent repository investigation tool

The problem was to turn repository context and an issue into an inspectable investigation, while making missing evidence visible. The implemented scope is one allowlisted public Go repository and a single-process Python service, with a small browser interface and persisted reports.

I selected gateway-rate-limiter after inspecting it and task-orchestrator live. The limiter had a smaller code surface, a real diagram-portability issue and concise source-level scenarios involving caller timeouts, script-cache errors, fail-open HTTP handling, IP identity and token refill. Expected evaluation facts came from reading the pinned source, not from asking the model to grade its own answer.

FastAPI accepts a job and returns immediately. A bounded worker resolves a commit, verifies downloaded blob hashes and retrieves original-line excerpts. Separate typed documentation, investigation and verification artifacts make the workflow inspectable. SQLite retains both final reports and intermediate progress/evidence. Markdown and JSON exports include exact source references. No target code executes, and the model has no tools or secrets.

The most important failure was in semantic verification: an initial model verifier accepted claims about external documentation rendering from unrelated source lines. Reference validity was working, but that did not establish claim support. I added per-claim allowed citation IDs, exact supporting quotations, and a deterministic gate for missing or mismatched quotes. A separate live probe then rejected fabricated production-performance and rendering-test claims while accepting a source-level interface declaration. This narrows the failure surface; it does not solve hallucination or prove entailment.

Other observed failures shaped the small design. Proposal filenames absent from the snapshot now appear as unverified rather than destroying a useful report. Missing or duplicated support judgments fail closed. Repeated anonymous GitHub requests hit a real rate limit and returned a visible failed run. Large verification payloads were reduced by indexing shared evidence once. Restart handling marks interrupted jobs failed without replaying paid calls, while completed reports remain on the persistent container volume.

The public Vercel deployment serves a saved actual-model report and both exports. The full FastAPI service is tested locally in Docker. No persistent remote host was configured, and the connected platform's daemon filesystem is ephemeral; I did not deploy SQLite there or claim it would survive restart. A real hosted backend needs the existing host configuration or an approved persistent database/worker architecture.

Raw application test results, deterministic retrieval/citation results, real model runs, attack probes, source-inspected review and container restart results are included. The final observed counts and latency/token totals are recorded in `evals/results/observed-results.json`. These are a small development evaluation, not production adoption, a benchmark against competitors or a validated performance improvement. Semantic false positives and conservative false negatives remain possible; independent human review is outstanding.
